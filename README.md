# 🍁 Maple

一个简洁的本地 AI 讨论室：你、Codex 和 Claude 在同一个聊天窗口里交流，DeepSeek 可以按需整理项目记录。

Maple 基于 [auspex0/Parley](https://github.com/auspex0/parley) 1.2.1 定制，保留上游 MIT 许可与作者信息。当前为早期预览版，提供源码及 Windows x64 免安装包。

## 有哪些变化

- 暖白底、枫叶图标和思源宋体；聊天正文与输入框为 17px，代码使用 JetBrains Mono。
- 默认中文界面，常用设置简化，较少使用的选项收在“高级设置”。
- 在聊天区直接选择模型与思考强度，无需反复打开设置。
- 默认额外额度为 2；“额外额度”控制自动接续，“账号额度”显示服务商提供的账户使用情况。
- 可选 DeepSeek 记录员：保留原始 Markdown 对话，手动整理摘要，检查后再让双方从摘要继续。

## 怎么开始

Windows 推荐用法：

1. 在 [下载页面](https://github.com/putianjie125-bit/Maple/releases/tag/v0.1.1) 获取 **Maple-0.1.1-windows-x64.zip**。
2. 解压到你喜欢的文件夹，双击根目录的 **start-maple.cmd**。应用包已内置 Node.js 运行时。
3. 安装并登录你要使用的官方 CLI：Codex 或 Claude Code。可以先只用其中一个，将另一个设为休眠。应用包不包含这些 CLI 和账号。

如果下载的是源码 ZIP，请先自行安装 [Node.js 22 或更新版本](https://nodejs.org/)。Windows 源码目录也提供同名启动脚本。

也可以在源码目录运行：

```sh
node parley.mjs
```

正常启动后会打开 `http://127.0.0.1:4141`。窗口只是本机网页，不是 Claude 或 Codex 的官方客户端。普通聊天通过本机 CLI 工作；DeepSeek 记录员需要单独的官方 API Key。

如果使用终端，可以指定数据文件夹：

```sh
node parley.mjs --root "D:/Maple/rooms" --port 4141
```

终端和 Windows 快捷启动默认都使用 `~/.maple`，即当前用户目录下的 `.maple` 文件夹。需要换位置时给启动脚本传入 `-DataDir`，或在终端使用 `--root`。不同数据目录的聊天室相互独立。

Windows 快捷启动如果没有检测到 Node.js，会显示安装提示并保留错误窗口。停止后台服务可在“项目记录 / 聊天室文件夹”保存好工作后关闭对应 Node 进程；命令行前台启动时按 Ctrl+C。

## 日常使用

- 直接输入：发送给当前默认或上次选择的智能体。
- `@codex`、`@claude`：指定谁回复。
- `@both`：双方参与讨论；请先确保双方均已登录并唤醒。
- 模型旁的“思考”：选择轻量、适中、深入等强度；列表根据当前模型目录提供，账号实际可用性由服务商决定。
- 额外额度 2：首次指定回复不计入，后续自动启动计入；它不是 token、金额或完整讨论轮数的保证。
- 👂 旁听会产生额外调用；不需要时保持关闭。

模型或思考强度切换会从下一条消息生效，并重新建立所选智能体的原生会话。原始聊天和已采用记忆保留；有任务在运行或排队时不能切换。

## 🤝 共识协商（Consensus）

共识协商默认关闭，是普通聊天之外的可选流程。Codex 和 Claude 平等讨论同一个文字任务，双方独立确认同一份完整方案后，程序才宣布达成共识。DeepSeek 继续担任项目记录员，不参与调度、提案、投票或裁决。

### 如何使用

1. 确保聊天室恰有一个 Codex 和一个 Claude 席位，均已安装、登录并唤醒；先完成或停止当前聊天、队列和待接续工作。
2. 在输入框上方的“交流方式”选择“🤝 共识协商（Consensus）”。
3. 选择最大轮数：1、2、3、5、10，或自定义 **1～20 的整数**，默认 **3**。
4. 在原有输入框填写文字任务，点“开始协商”（或按 Enter）。目前共识任务仅支持文字，不携带附件、项目记忆或旧聊天上下文；需要的背景请写入任务。
5. 面板可查看状态、当前候选、双方确认、最终共同方案、尚未解决的分歧及历史任务；“停止协商”和聊天室原有 Stop 都能终止共识任务。停止一方会停止整场协商，避免留下不平等的单方流程。

协商期间暂不接受该聊天室的普通发送、Retry、设置或新对话操作，防止插入额外讨论。结束或停止后可切回“普通聊天”。其他聊天室照常工作。普通聊天的调度器、自动接续额度、原生会话和 DeepSeek 记录功能保留。

### 轮数与双方确认

**一轮 = Codex 和 Claude 各获得一次实质性讨论机会。初始独立回答计第 1 轮；最终确认不计讨论轮数。** 每阶段同步启动双方，双方都完成后才公开回复；响应更快不会获得更多讨论机会。

双方都可以提交完整候选方案、修订或否决。相同内容只确认一次；不同提案都可以进入双边确认，奇数轮先考虑 Codex 的方案、偶数轮先考虑 Claude 的方案。前一份若已获双方接受就立即停止，不再调用模型；否则继续检查另一方的提案，随后把双方分歧和修改意见送入下一轮。此顺序只用于有限提案的检查，不代表任何一方拥有裁决权。

每份候选有递增版本号、完整原文和 UTF-8 内容的 SHA-256。双方收到完全相同的候选内容，使用独立的新 CLI 会话返回结构化 `AGREE` / `DISAGREE`、自身身份、版本、哈希和理由；确认时间由程序记录。双方完成前不公开任何本次确认结果。只有**双方都有效返回 AGREE，且身份、版本、哈希全部匹配**才进入 `CONSENSUS_REACHED`。任何改动都产生新版本和空的确认记录；旧确认只作审计历史。无效 JSON、自然语言“已达成共识”、送达成功、调用失败或超时均不能算同意。

### 状态解释

| 状态 | 含义 |
| --- | --- |
| `IDLE` | 尚未启动 |
| `DISCUSSING` | 正在独立回答或交换观点 |
| `PENDING_CONFIRMATION` | 等待双方独立确认当前版本 |
| `CONSENSUS_REACHED` | 双方有效确认了同一版本和哈希 |
| `UNRESOLVED` | 轮数用尽，仍无双方共同确认的方案 |
| `STOPPED` | 用户主动停止，迟到的结果不会恢复任务 |
| `FAILED` | CLI、协议或系统失败；或重启时发现协商中断 |

每次任务的原问题、ID、状态、轮数、调用阶段、讨论、各版候选、确认和分歧，原子保存于聊天室目录的 `consensus/tasks/<任务ID>.json`。重启只恢复记录，不自动续跑或重新调用模型；中断任务标记 `FAILED`。已完成记录只有通过双边确认与内容完整性检查才保留成功状态。新对话仍可查阅共识历史；它不会删除原聊天记录。

### Token 与资源消耗

最多进行设置的讨论轮数，每轮双方各讨论一次。没有候选时只调用 2 次；一个候选最多 4 次；两个不同候选最多 6 次（包括独立确认）。例如 3 轮最多 6 次实质性讨论调用，以及 12 次确认调用，共 18 次。确认不是额外讨论机会，也不会触发普通自动接续、旁听或隐式重试。达成共识立即结束。

面板显示真实调用尝试次数；CLI 确实返回的 token 字段保存在调用记录和消息用量中，缺失字段不会估算，不能把部分字段当作总 token。每轮带入原任务、上一轮双方观点、候选与拒绝理由；完整历史留在本地，避免上下文无限追加。模型额度由你登录的 CLI 账户承担。每次调用受设置中的“超时时间（秒）”约束，共识流程另有最长 30 分钟的单次调用上限；超时或模型失败后终止，不默认同意。可随时手动停止并终止 CLI 进程树。

### 常见问题

- **双方说“达成共识”为什么仍未成功？** 必须对同一版本和哈希独立返回有效确认；自然语言不能改变程序状态。
- **只有一方同意怎么办？** 记录拒绝理由，继续下一轮；用尽轮数则显示未解决，最后一份候选不会自动成为共同结果。
- **修改方案后还要确认吗？** 需要，任何修改都会生成新版本并清空当前确认。
- **为何不使用旧原生会话？** 初始观点与确认需要隔离。共识每次调用都使用新会话、独立空目录和只读权限请求；不会覆盖普通聊天会话，也不接受房间的自定义 CLI 附加参数。CLI 包装程序和供应商全局配置仍属于本地信任边界。
- **DeepSeek 能帮忙裁决吗？** 不能。它只能按既有方式记录或总结已公开的讨论，不拥有共识状态或确认的写入接口。
- **共识就是正确答案吗？** **模型达成共识不等于方案已经得到客观验证。** 证据、计算、实验、安全性和真实可行性仍需另行验证。

开发验证：`npm test` 包含共识单元与模拟 CLI API 测试；`npm run test:integration` 检查原有调度回归；`npm run test:browser` 包含真实页面操作。全部使用模拟模型，避免消耗真实额度。

## DeepSeek 项目记录

记录员是可选功能，不填写 Key 也能正常聊天。当前整理模型固定为 `deepseek-flash`，使用 DeepSeek 官方接口；请确认自己的账户实际支持该模型。

1. 打开“项目记录”，填写官方 API Key 和需要的本机文件夹。
2. 有对话后点“整理记录”；这会把需要整理的对话和相关已有记忆发给 DeepSeek，并产生 API 费用。
3. 检查摘要，必要时填写修订说明。
4. 点“用这份记录继续”，双方后续从共同记忆与最近对话接续。

原始对话保留；摘要可以修正，不能代替原始证据，也不会自动授权执行其中的建议。附件正文不会自动复制进记录或发送给记录员。

当前 API Key 保存使用 **Windows DPAPI**，只在当前 Windows 用户下解密。macOS/Linux 可运行基础聊天室，但本版尚未提供这些平台的记录员密钥存储，也未验证其日常使用兼容性。

## 账号额度

- Codex：读取 CLI 提供的账户额度元数据，和其他使用同账号的客户端共享。
- Claude：从普通回复中的限额事件读取；没有拿到数据时显示“未获取”，不猜测百分比。
- DeepSeek：只显示官方余额。

Codex 重置卡仅在接口实际返回可用卡时显示。点击消耗一张需要明确操作；刷新页面不会使用卡。Claude 提供官方用量页入口，不伪造一键重置。

## 权限与数据

新安装默认采用对话模式和保守权限。需要修改文件时再切换工作模式，并选择合适的项目文件夹。完全访问属于高级选项，不是推荐默认值。CLI、操作系统及明确的用户要求仍然决定实际权限范围。

个人偏好、聊天数据、密钥和日志不属于源码。本仓库没有作者本机的账号配置、自动审批配置或聊天记录。字体随源码离线提供，许可位于 `ui/fonts`；没有打包 SF Mono 或 Anthropic 字体。
